# Reference implementations

Two self-contained files that implement the mechanics documented in `../docs/`:

| File | What it does | Self-test |
|---|---|---|
| `auth_build.py` | builds the authentication message (device id, `ht`, protobuf fields), wraps it in the envelope (OAEP-SHA512 + AES-256-GCM), sends it, and decrypts the response | `python auth_build.py` → size identities + envelope round-trip |
| `pipe_proto.py` | 26-byte IPC frame codec and the four reply builders (`0x65` 1250 B, `0x09` 40 B, `0x04` 40 B, `0x3EB` 36 B) | `python pipe_proto.py` → all sizes asserted |
| `pipe_server.py` | Windows named-pipe server that answers the client using `pipe_proto` (identity read from a JSON file, never hardcoded) | Windows only |

## Requirements

```
python >= 3.10
cryptography >= 41        # auth_build.py
```

## Quick start

```bash
# 1. plumbing check (no network, no credentials)
python pipe_proto.py
python auth_build.py

# 2. serve the IPC endpoint (Windows, administrator)
#    identity.json: {"player_id": "...", "token": "...", "session_id": "..."}
python pipe_server.py identity.json
```

## What these files deliberately do **not** do

1. **They cannot produce an accepted authentication request.**
   Two device-identifier parts (`p2`, `p3`, 64 bytes each) are generated by a secret that never
   leaves kernel mode. They are stable across sessions and were not reproducible from any readable
   hardware value (234,234 hash combinations tested). `auth_build.py` therefore builds a
   syntactically valid request, not an accepted one.

2. **They do not implement the integrity fields `htt` / `gg`.**
   Their validation is proven (random values are rejected) but their derivation is unknown.

3. **They do not bypass anything.**
   The IPC server only speaks the protocol the client expects. Sending an authentication request
   to the gateway is itself a detection signal: in this study accounts that sent one were banned
   within 0.5–2.7 s (8/8, small sample, single environment).

## Why publish them anyway

The wire format is the reusable part. It lets researchers:
- validate their own captures against a known-good encoder,
- build test harnesses with deterministic frames,
- check whether a behaviour difference comes from framing or from content.

That is the same reason packet-format libraries exist for other protocols.

## Ethical note

Using these files against live services violates the Riot Games Terms of Service, will get
accounts permanently banned, and can harm other players. They are published for defensive
research and protocol education.
